# Generated tables stay TSV; JSONL is for rows that are not flat

`docs/adr/0002-committed-generated-index-tables.md` ruled that generated tables are committed and
have exactly one writer, but it said nothing about the format, so every plan since has had to
re-decide it. This is that decision, made once.

**TSV is the default for generated tables, not a legacy format awaiting migration.** It won on a
measured property, not a habit: our free text is comma-bearing and tab-free. Of 2079 rows in
`disasm/index/footprint.tsv`, 1619 contain a comma, and all 120 rows of `disasm/census/creature.tsv`
do. Switching those to CSV would force quoting on the majority of rows, which turns a reviewable
diff into escaped noise and makes grep quietly wrong. The `# generated by <tool> -- do not
hand-edit` header line is also load-bearing: it is how the sole-writer rule is self-enforcing at
the point of use, and TSV can carry it.

**JSONL is the choice when a row is genuinely nested** — alias lists, several evidence citations
for one claim, per-leg grades that vary in count. A JSON object per line carries types and real
nulls, needs no extra table for a multi-valued field, and is read natively by DuckDB. Its cost is
concrete: JSONL has no comments, so a JSONL table must ship a sidecar carrying the do-not-hand-edit
marker and the column contract that a TSV header holds inline. Prefer splitting into more rows over
reaching for nesting; a flat table in JSONL pays the cost and buys nothing.

**The split is by shape, never by age.** "TSV is legacy, migrate as needed" was rejected because
migrating a generated table is free — you regenerate it — so the migration is never the hard part.
What "as needed" produces instead is a tree permanently split in two, every tool handling both
formats, and no rule for which a new table should use. A rule with a test beats a preference with
an expiry date.

**A format change is not the fix for the defect that actually happened.** TSV carries no types and
no null distinction, and empty interior fields are the norm rather than the exception (1209 of 1212
rows in `coverage.tsv`, 2062 of 2079 in `footprint.tsv`). During the record-index planning an agent
filtered `footprint.tsv`'s offset column as hex when it holds decimal, got zero rows, and reported
an absence of evidence — nothing in the file named its own base. The fix is a **column contract**
declared by the generator and asserted by `--verify`: every column's type and base stated, and every
value checked against it. That is cheap, it addresses the failure that occurred, and it removes most
of what JSONL would otherwise be needed for in a flat table.

## Considered Options

**CSV** was rejected on the measurement above: our text contains commas, so escaping is not an edge
case but the common case. **A committed SQLite or DuckDB file** was rejected because it is not
reviewable in a diff, which is the property ADR 0002 exists to protect, and it would be a second
copy of facts already in text. **DuckDB as a query surface over the committed TSV** is explicitly
allowed and encouraged — `read_csv_auto` reads these files directly, so SQL is available without
duplicating anything; a derived `.duckdb` is a gitignored artefact, never a source of truth.
**YAML** was rejected earlier for the fact store and remains rejected: indentation-sensitive, slow
to parse, and it reflows in ways that make diffs lie. **JSONL for everything new** was rejected as
the same fork-by-another-name, since a format chosen because it is newer is a preference, not a rule.

## Consequences

Every new generated table names its shape — flat or nested — before it names its format, and a
JSONL table ships its sidecar in the same commit. Every generator declares its column contract and
`--verify` enforces it, so a column's base and type are checkable rather than tribal knowledge.
Existing TSV tables are not migrated for format's sake; they gain the contract when a change
touches them anyway. `tools/generated_fresh.sh` and `tools/check_all.sh` keep handling one
extension by default, and gain JSONL support only when a nested table actually exists.
